# UI previews

Explain the user-visible delta. Do not review it, score it or call it better. `ui-review` judges; this skill names what changed, where, why, and what proves it.

A delta is one observable difference: a label, state, layout, control, motion or enabled/disabled rule. Code that only changes a test, comment, type or internal path is not a UI delta; list it under **Not UI**, not as a numbered delta.

## Output contract

- **Primary artifact:** `<evidence-dir>/report.html`, generated by `scripts/build-report.mjs` from `<evidence-dir>/deltas.json` with the PNGs beside it. Relative image paths, inline CSS, no dependencies, no JavaScript.
- **Chat reply:** one sentence naming what an operator now sees differently, the report path, and the verification line. The old markdown delta table is retired; keep it only for the no-runtime fallback below. Chat copy follows the user's language; report copy is English.
- **Never commit** `.ui-previews/` unless asked. Keep the original PNGs; callout boxes are drawn at render time, never baked into the evidence.

## Report anatomy

1. **Masthead:** title, base→head refs, fixture, viewport, theme, date, the one-sentence summary, and the legend.
2. **One numbered card per delta:** a plain `1.` prefix, section title ("Pricing — annual price"), why, source `file:line`, and a before/after pair with BEFORE/AFTER labels above the images, cropped to the same window around the changed component, with orange boxes on both images.
3. **Evidence sections:** Unchanged, Not UI, Not observed, Verification. Keep all four even when empty; the builder writes "None recorded." for an empty list.

Visual contract:

- Page background `#FAFAF8` (not pure white), cards `#FDFCFA`, centered column `min(1120px, 100% - 40px)`, **text left-aligned inside the column**, light theme only.
- Callout: `#F97316` 2px outline, no fill. No number badge on the screenshots; the card number is plain orange text in the heading (`1.`). Orange is reserved for the change boxes.
- Boxes are padded 6 CSS px beyond the measured rect for breathing room; boxes on the same side that overlap after padding are merged into one box. A box covering ≥95% of its crop is rejected — mark the changed component, not the viewport.
- The builder crops both images of a card to the same window: the union of that delta's rects, 35% padding clamped to 64–200px, minimum 320×180 CSS px, clamped to the viewport. Each screenshot links to its full viewport capture.
- A removed element gets no dashed anchor and no absent label. Give both sides the same container rect (the nav, card or page area), never the whole viewport or a band wider than the component; the box marks that component and the difference sits inside it. Explain the removal in `why`.
- Each shot has a small BEFORE/AFTER label above it; the pair shares one route line below, with the state appended only when it is not `idle` (e.g. `/billing · hover`). Do not repeat route, state or a capture link under both images. At 760px and below the pair stacks.

## Steps

1. **Fix the pair.** Record base and head refs, the changed files, and every route or component they reach. Read the diff before opening the app. Completion: each changed file is classified UI, UI state, or not UI, and the routes to inspect are listed.

2. **Render both states.** Use the same fixture, seed, viewport (1440x900), theme and route for both refs. Prefer the project's browser/e2e harness. Scroll the changed region into view on each ref; the two sides may need different scroll positions when layout shifted. Capture the **viewport only**, not full page; the builder crops each card around its delta. Reuse one PNG pair per route + state across deltas. Completion: every delta has a before and after at matched conditions, or a `notObserved` reason.

3. **Measure the region per ref.** After fonts and images settle, read `getBoundingClientRect()` (or the harness's `boundingBox()`), in CSS px, separately on each ref. Do not reuse before coordinates on after. If a block's text is narrower than its box, measure the text with `Range.getBoundingClientRect()` so the callout hugs the changed words instead of empty width. If the rect is in page coordinates, subtract `scrollY`; if it is in device pixels, divide by `devicePixelRatio`. For an element inside an iframe or shadow root, add the frame offset so the rect lands in viewport coordinates. For an element that exists on one side only, use the container rect (e.g., the whole nav) on both sides and describe the removal in `why`. Completion: every region has a rect on both sides.

4. **Name the delta.** For each pair, write the exact rendered text or measurable property, the route, the state (idle, hover, focus, selected, error, loading, disabled), and the trigger. Completion: every card is reproducible from `deltas.json` and the PNGs.

5. **Explain the mechanism.** `why` must come from the commit/PR message or the code condition that produces the render, with a `file:line` source. If the intent is not stated anywhere, prefix `[inferred]` and say it is deduced from the diff. Never invent a rationale, and never attribute a reason to the user that they did not state. Completion: no visual claim without a source location or an `[inferred]` label.

6. **Build the report.** Write `deltas.json` (schema below), then:

   ```sh
   node ~/.agents/skills/ui-previews/scripts/build-report.mjs .ui-previews/<date>-<surface>/deltas.json
   ```

   The builder has no dependencies and requires Node 18+. It validates the refs, pair files, PNG dimensions against the viewport, and every rect; it writes `report.html` beside the JSON and computes each card's crop window. A validation error is a gap to fix, not something to paper over.

7. **Verify and report.** Open `report.html` at 1440px and 390px. Confirm every crop shows the changed component at a readable size, the boxes sit on the changed content on both sides, and nothing overflows. Run the cheapest check that covers the page. Then reply with the one-sentence delta, the report path, and `Verification: <command> — <result>; evidence: <dir>`.

## deltas.json

```jsonc
{
  "title": "Home — pricing",
  "base": { "label": "main", "ref": "a1b2c3" },
  "head": { "label": "feat/pricing", "ref": "d4e5f6" },
  "fixture": "seeded demo@example.com, 3 projects",
  "viewport": { "width": 1440, "height": 900 },
  "theme": "light",
  "date": "2026-11-27",
  "summary": "Pricing cards now quote the annual price; the monthly toggle moved below the card.",
  "pairs": [
    {
      "id": "home-idle",
      "route": "/",
      "state": "idle",
      "before": "shots/01-before.png",
      "after": "shots/01-after.png"
    }
  ],
  "deltas": [
    {
      "n": 1,
      "title": "Pricing — annual price",
      "why": "The annual plan became the default, so the card quotes its price.",
      "source": "src/pages/index.astro:88",
      "pair": "home-idle",
      "before": [{ "x": 820, "y": 310, "w": 260, "h": 180 }],
      "after": [{ "x": 820, "y": 310, "w": 260, "h": 180 }]
    }
  ],
  "unchanged": ["Monthly toggle still exists below the card."],
  "notUI": ["Pricing helper type widened."],
  "notObserved": ["390px pricing card was not captured."],
  "verification": { "command": "pnpm check", "result": "0 errors" }
}
```

| Field | Rule |
|---|---|
| `n` | Unique positive integer; cards render in `n` order. |
| `title` | Section + element, e.g. "Header — Docs link". |
| `why` | Sourced rationale, or a sentence prefixed `[inferred]`. |
| `source` | `file:line` (or `[inferred] …` when no source exists). |
| `pair` | Id of a pair above. Pairs are reused across deltas. |
| `before` / `after` | Rect arrays `{x,y,w,h}` in CSS px of the recorded viewport. At least one side non-empty. |
| `crop` | Optional `{x,y,w,h}` in viewport CSS px. Overrides the computed crop; must leave at least 6px around every rect and fit the viewport. Use it to widen the context around the box, not to turn the box into a viewport frame. |
| `notObserved` | Replaces `pair`/`why`: a reason string renders a muted numbered card in place. Use it when a visible delta could not be captured; use the top-level `notObserved` list for states that are not a delta. |
| `pairs[].before/after` | PNG paths relative to `deltas.json`. |
| `unchanged`, `notUI`, `notObserved` | String arrays; an empty list renders "None recorded." |
| `verification` | `{ "command": "...", "result": "..." }`. |

Rects are CSS pixels, never device pixels. The builder rejects screenshots whose aspect ratio differs from the viewport by more than 1%, because full-page or cropped captures cannot be mapped back to the measured rects. Without a `crop`, the builder derives one per delta from the union of its rects; a manual `crop` must leave 6px around every rect.

A pair's `state` is required evidence of matched capture conditions, but the report hides `idle`; it prints only a non-default state such as `hover`, `focus`, `error` or `loading`.

For a removed element, use the same container rect on both sides (e.g., the whole nav), not the whole viewport or a full-width page band; explain the removal in `why`. The old `absent`/dashed marker is rejected.

```jsonc
// Removed nav item: box the nav container on both sides.
{
  "n": 2,
  "title": "Header — Docs link",
  "why": "The Docs link was removed from the primary navigation.",
  "source": "src/components/Nav.astro:24",
  "pair": "home-idle",
  "crop": { "x": 1158.92, "y": 0, "w": 265.08, "h": 87 },
  "before": [{ "x": 1198.92, "y": 28, "w": 185.08, "h": 19 }],
  "after": [{ "x": 1259.05, "y": 28, "w": 124.95, "h": 19 }]
}
```

The after box is narrower because `Docs` is gone; no `absent` field, both boxes solid.

## Evidence rules

- **Same conditions or no comparison.** If before and after use different fixtures, dates, viewports, themes or wallet selections, the pair is not a delta. Fix the fixture or say why it cannot be fixed.
- **Record the refs.** A screenshot without the base/head ref and fixture is an anecdote. Put both in the report.
- **Interact through the page.** Reach hover, focus, open, error and disabled states with real page interactions. Do not inject a class, edit React state or reveal a hidden element to manufacture the after shot. If a state cannot be reached, say so.
- **No production edits for evidence.** A temporary harness is allowed when it is the only way to seed a state; remove it before the report and leave the branch unchanged.
- **Broken image is not evidence.** Check every capture loads at its natural size. A blank tile is a gap, not a change.
- **Identical pair is not evidence.** The builder rejects byte-identical before/after PNGs; capture the state that shows the change or mark the delta `notObserved`.
- **No taste verdicts.** "Cleaner", "better", "more polished" are out unless the caller asked for a judgement; that request belongs to `ui-review`.
- **A source-only answer is labelled.** Without a runtime, the explanation is `[inferred]` from the diff, and the report says what could not be observed.
- **Overlays are evidence too.** A box that does not sit on the changed element is a false claim; re-measure or mark the delta `notObserved`.

## No-runtime fallback

If no screenshot can be captured for the whole diff, produce the previous markdown table in chat, labelled `[inferred]` per visual claim, and state which states were not exercised:

| Surface | Before | After | Evidence |
|---|---|---|---|
| Exact route and element | Exact text/state/property | Exact text/state/property | Diff path or `[inferred]` |

Follow it with **Why it changed** (source per row), **Unchanged**, **Not UI**, and **Not observed**. Do not create `report.html` with placeholder images. If only some deltas cannot be observed, keep the HTML report and give each of those deltas a `notObserved` card in its numbered slot.

## Done

Every numbered card has a matched before/after pair or a `notObserved` reason; every pair records refs, fixture, viewport, theme and scroll; every crop shows the changed component at a readable size, with boxes aligned on both sides; every visual claim has a source location or `[inferred]`; the report opens at 1440 and 390 without overflow; the chat line names the check and its result.
